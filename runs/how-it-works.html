How it works

A learning-curriculum agent: goal + time budget + learner profile in, an ordered, justified curriculum out. This page explains how the agent works, every design decision and why, and how it is evaluated.

The agent

A tool-using loop, not fixed stages. The model plans, then decides each move for itself — search, read, choose — over a bounded number of turns. Code, not the model, enforces the rules it can't be trusted with.
1
Plan
From the learner profile it names 3–7 ordered sub-topics with prerequisites, judges whether the goal is feasible in the budget, and narrates what it is about to do — the narration you see streaming live.
2
search_youtube(query)
It issues its own queries — one per sub-topic, plus a project-style query that mirrors the goal — against a candidate pool gathered from YouTube search (yt-dlp by default; the official Data API when a key is set). View count is returned but the prompt is explicit that popularity is not fit.
3
read_video(video_id)
The only way to learn what a video teaches: a content summary, level, format, red flags, topics covered, and verbatim quotes with ids and timestamps. It reads only as many as it needs to choose well — typically far fewer than the whole pool.
4
submit_curriculum(…)
When the plan is covered it submits picks in watch order, each with the sub-topics it covers, a reason, the verified quote ids backing that reason, an optional watch range, a confidence, and a list of strong candidates it read but dropped.
5
Verify (in code)
Every submission runs the same guardrails as a code pipeline would: ids must be in the pool, only quotes verified against the transcript may be cited, the budget must hold, flagged picks are replaced when an unflagged alternative exists, and the learner's stated limits are applied. A submission that fails is handed back to the agent to fix.
Why a loop, not a chain? The agent reads only what it needs, can back out of a dead end, and — because the model that built the curriculum is still in the conversation — it can defend each choice and revise on request with its real working context, not a reconstruction. Transcript grounding, quote verification, assessment and assembly are shared library code, so the loop is about who decides, never about cutting corners on the checks.

Design decisions, and why

DecisionWhy
An agent loop, and it stays to defend its workThe model drives search → read → choose itself, then remains in the conversation to answer 'why this video?' and to revise on request — with its real working context, not a reconstruction. Grounding is still enforced in code, so the openness costs nothing on correctness.
Read the transcripts, not titles or viewsThe brief's premise is that popularity and titles don't tell you fit. Reasons must quote what is actually said. The 'no transcript' baseline in the eval measures what reading buys.
Quotes verified in code and cited by idThe selector can only cite quote ids that code already found in the transcript, so a reason cannot be backed by invented evidence. Grounding is enforced, not requested.
Cheap model reads, strong model chooses~30 extraction calls per run go to the cheap model (Haiku); planning and selection, where judgement matters, go to Sonnet 5.5. The split is tested by the model comparison, not assumed.
Code owns the arithmetic and the hard rulesBudget sums, valid ids, quote ids, red-flag replacement and the learner's stated limits (recency, sitting length, creators) are checked in Python. Models are unreliable at arithmetic and rule-following under pressure.
Dedup from topic labels, not embeddingsFree, explainable, and guarded by level and format so a beginner explainer and an advanced build are not merged.
Degrade honestly when YouTube blocks transcriptsFall back to chapters and description, label that evidence as weaker everywhere, and don't work around the block with scrapers or proxies. A hosted provider on the user's own key can fill gaps if configured.
Judge from a different model familyA model preferring its own outputs would inflate the scores, so OpenAI/Google models judge the Anthropic curator's picks, in both orders, with binary verdicts and critiques rather than drift-prone scores.

How it's evaluated

Three layers, decided before looking at any output:

  1. Deterministic checks (no model): invented ids, budget overrun, constraint and red-flag violations, known-topic leakage, unverified quotes, level floor, language, and the learner's stated limits. Hard checks gate a pass.
  2. LLM judges from another model family: a per-criterion rubric with written critiques, pairwise comparisons against both baselines in both orders, and a faithfulness check that each reason's claims are supported by the video's text.
  3. Human labels (blind) to measure whether the judge can be trusted.

Two baselines run on the same candidate pool: the agent without transcripts, and the top videos by view count. See the evaluation page for results.

What it deliberately does not do

  • Measure teaching quality beyond what is said — pacing, audio and on-screen code are not seen.
  • Work around YouTube's caption block with scrapers or proxies; it degrades to weaker evidence and says so.
  • Promise a learner reaches the goal — every number is a proxy for 'a careful mentor would pick this'.
